## 0. 공통 규칙 (전 도메인 적용)

### 공통 응답 포맷

```json
{
  "code": "SUCCESS",
  "message": "OK",
  "data": {}
}
```

```json
{
  "code": "COMMUNITY_001",
  "message": "존재하지 않는 게시글입니다.",
  "data": null
}
```

> `data`가 null인 경우 `@JsonInclude(NON_NULL)`에 의해 응답 JSON에서 생략된다.

### 공통 응답 클래스

```java
// com.chunbaetour.domain.common.response.ApiResponse
@JsonInclude(JsonInclude.Include.NON_NULL)
public record ApiResponse<T>(String code, String message, T data) {

    private static final String SUCCESS_CODE = "SUCCESS";
    private static final String SUCCESS_MESSAGE = "OK";

    // 데이터 있는 성공 응답
    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(SUCCESS_CODE, SUCCESS_MESSAGE, data);
    }

    // 데이터 없는 성공 응답 (삭제 등)
    public static ApiResponse<Void> success() {
        return new ApiResponse<>(SUCCESS_CODE, SUCCESS_MESSAGE, null);
    }

    // 에러 응답
    public static ApiResponse<Void> error(String code, String message) {
        return new ApiResponse<>(code, message, null);
    }
}
```

### BaseEntity (모든 Entity 상속)

```java
@Getter
@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class BaseEntity {
    @CreatedDate
    @Column(nullable = false, updatable = false)
    private LocalDateTime createdAt;

    @LastModifiedDate
    @Column(nullable = false)
    private LocalDateTime updatedAt;
}
```

### 패키지 구조 원칙

```
com.chunbae.tour.domain.{domainName}
├── controller
├── service
├── repository
├── entity
├── dto
│   ├── request
│   └── response
└── type
```

- Controller → Service만 호출, 비즈니스 로직 금지
- Entity → Controller 응답으로 직접 반환 금지, DTO 사용
- 삭제는 Soft Delete 기본 (`deletedAt` 필드 각 Entity에 관리)
- 상태값은 Enum으로 관리
- **사용자 유형(USER/ADMIN)에 따라 접근 범위가 다른 도메인은 같은 도메인 패키지 안에서 Controller를 분리한다.**
  - 예: `domain/report/controller/ReportController.java` (USER 전용) + `domain/report/controller/AdminReportController.java` (ADMIN 전용)
  - 예: `domain/festival/controller/FestivalController.java` (USER GET) + `domain/festival/controller/AdminFestivalController.java` (ADMIN CRUD)
- **모든 Service 클래스는 클래스 레벨에 `@Transactional(readOnly = true)`를 선언한다. 데이터 변경이 필요한 메서드에만 `@Transactional`을 개별 오버라이드한다.**

```java
@Service
@Transactional(readOnly = true)  // 클래스 레벨 — 모든 메서드 기본값
@RequiredArgsConstructor
public class PostService {

    @Transactional  // 쓰기 메서드만 오버라이드
    public PostResponse createPost(...) { ... }

    public PostResponse getPost(...) { ... }  // readOnly 상속
}
```
