# 에이전트 최초 진입점

이 파일은 춘배투어 작업을 시작하는 모든 에이전트의 첫 진입점입니다.

목적은 에이전트가 작업 범위를 임의로 넓히지 않고, 필요한 기능 하네스 안에서만 움직이게 하는 것입니다.

## 반드시 읽는 순서

1. 이 파일을 읽습니다.
2. [에이전트 온보딩 가이드](./agent-onboarding.md)를 읽고 프로젝트 전체 구조를 확인합니다.
3. [박경화 담당 도메인 정리](./park-kyunghwa-domain.md)를 읽고 담당 범위를 확인합니다.
4. [전역 가드레일](./agent-harness/global-guardrails.md)을 읽고 금지·보고 조건을 확인합니다.
5. 작업 요청에 맞는 기능별 하네스 하나만 먼저 읽습니다.
6. 둘 이상의 기능이 얽히면 [하네스 라우터](./agent-harness/README.md)의 다중 기능 규칙을 따릅니다.

## 기능별 하네스 선택

| 사용자 요청 | 먼저 읽을 하네스 |
|---|---|
| 게시판, 게시글, 커뮤니티 글 | [Community Post 하네스](./agent-harness/community.md) |
| 댓글, 게시글 댓글 | [Comment 하네스](./agent-harness/comment.md) |
| 신고, 신고 처리, 신고 사유 | [Report 하네스](./agent-harness/report.md) |
| 축제, 행사, 캘린더 | [Festival 하네스](./agent-harness/festival.md) |
| 관광지 리뷰, 별점 | [Review 하네스](./agent-harness/review.md) |

## 작업 시작 전 체크

작업을 시작하기 전에 다음 질문에 답할 수 있어야 합니다.

| 질문 | 기준 |
|---|---|
| 박경화 담당 도메인인가? | 게시글, 댓글, 신고, 축제·캘린더, 관광지 리뷰만 해당 |
| 어떤 기능 하네스인가? | 기능별 하네스 하나로 시작 |
| 보호 파일 수정이 필요한가? | 필요하면 작업 중단 후 박경화에게 보고 |
| 타 도메인 직접 수정이 필요한가? | 필요하면 작업 중단 후 박경화에게 보고 |
| 요구사항이 애매한가? | 추론하지 말고 질문 |
| 구조 변경이 큰가? | 작업 전 보고 |

## 보호 파일

다음 파일은 기본적으로 직접 수정하지 않습니다.

| 파일 또는 경로 | 규칙 |
|---|---|
| `.env` | 직접 수정 금지 |
| `.env.example` | 사전 보고 후 수정 |
| `src/main/resources/application.yml` | 사전 보고 후 수정 |
| `src/main/resources/application-*.yml` | 사전 보고 후 수정 |
| `src/main/resources/application-*.yaml` | 사전 보고 후 수정 |
| `src/main/resources/application-*.properties` | 사전 보고 후 수정 |
| `docker-compose.yml` | 사전 보고 후 수정 |
| `build.gradle` | 사전 보고 후 수정 |
| `settings.gradle` | 사전 보고 후 수정 |
| `src/main/java/com/chunbaetour/domain/auth/**` | 읽기만 허용, 직접 수정 금지 |
| `src/main/java/com/chunbaetour/domain/common/**` | 공통 영향이 있으므로 사전 보고 후 최소 수정 |
| 박경화 담당 외 도메인 | 직접 수정 금지 |

## 즉시 중단하고 보고해야 하는 경우

다음 중 하나라도 해당하면 구현을 멈추고 박경화에게 먼저 보고합니다.

| 상황 | 보고 내용 |
|---|---|
| 보호 파일 수정 필요 | 왜 필요한지, 수정하지 않을 대안이 있는지 |
| Auth, Security, Common 수정 필요 | 영향 범위와 대안 |
| 다른 담당자 도메인 수정 필요 | 어떤 도메인인지, 왜 직접 수정이 필요한지 |
| 새 의존성 추가 필요 | 라이브러리명, 목적, 대안 |
| API 경로 또는 응답 형식 변경 필요 | 기존 계약과 변경 이유 |
| 엔티티 관계가 여러 도메인으로 번짐 | 연쇄 변경 범위 |
| 패키지 이동, 대규모 리팩터링 필요 | 변경 전후 구조 |
| 요구사항이 둘 이상으로 해석됨 | 가능한 해석과 추천안 |
| 테스트 실행에 Docker, 네트워크, 권한 문제가 필요 | 필요한 명령과 이유 |

## 애매할 때의 원칙

애매하면 추론하지 않습니다.

다음 형식으로 보고하고 의견을 묻습니다.

```text
확인이 필요합니다.

요청:
- 사용자가 말한 요구사항

애매한 지점:
- 해석 A
- 해석 B

추천:
- 저는 A를 추천합니다.

이유:
- 기존 구조와 더 잘 맞는 이유

진행해도 될까요?
```

- 어떤 파일을 수정했는지

- 보호 파일을 건드렸는지

- 남은 리스크나 확인 필요 사항이 있는지
