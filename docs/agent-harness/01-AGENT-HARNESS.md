# 01-AGENT-HARNESS.md

이 문서는 모든 에이전트가 반드시 지켜야 하는 안전 규칙이다.

## 절대 금지

사용자 명시 승인 없이 다음 작업을 하지 않는다.

- `main` 브랜치 직접 push
- PR 자동 merge
- 운영 서버 직접 수정
- 운영 DB 직접 조작
- secret, token, password 하드코딩
- `.env` 파일 커밋
- 외부 API 비용이 발생하는 작업
- 아키텍처 변경
- 패키지명 변경
- MVP 범위 변경
- 사용자 변경사항 되돌리기
- force push

## 보호 파일

다음 파일은 사용자 승인 없이 수정하지 않는다.

- `application.yml`
- `application-*.yml`
- `application.properties`
- `application-*.properties`
- `.env`
- `.gitignore`
- 배포 secret 파일
- CI/CD credential 파일

예외:

- 사용자가 명시적으로 요청한 설정 작업
- 로컬 개발 환경 개선 작업에서 승인된 설정 변경

예외가 있으면 작업 완료 보고에 변경 이유를 적는다.

## 승인 필요 작업

다음 작업은 먼저 사용자에게 보고하고 승인받는다.

- DB 스키마 변경
- Entity 필드 추가, 삭제, 타입 변경
- 운영 설정 변경
- CI/CD 배포 방식 변경
- 외부 API 추가
- 인증, 권한, 보안 정책 변경
- Docker 기본 포트 변경
- 브랜치 전략 변경
- 대량 리팩토링

## 작업 중단 조건

다음 상황에서는 작업을 멈추고 사용자에게 보고한다.

- 테스트 실패 원인을 확정할 수 없음
- 사용자 변경사항과 충돌함
- 보호 파일 수정이 필요함
- DB 구조 변경이 필요함
- 운영 환경에 영향이 있음
- secret으로 보이는 값이 발견됨

## 에이전트 행동 원칙

- 기존 코드 스타일을 먼저 따른다.
- 필요한 파일만 읽는다.
- 작업 범위를 임의로 넓히지 않는다.
- 변경 전후의 의도를 짧게 설명한다.
- 문서와 코드가 충돌하면 사용자에게 확인한다.
