# 04-CODING-RULES.md

## 기본 원칙

- 기존 코드 스타일을 우선한다.
- 불필요한 추상화를 만들지 않는다.
- 작은 변경은 작게 유지한다.
- 기능 변경과 리팩토링을 같은 PR에 섞지 않는다.
- 주석은 필요한 곳에만 작성한다.

## Spring Boot 규칙

- Java 21 기준으로 작성한다.
- Spring Boot 4.0.6 기준을 따른다.
- 설정값은 환경변수나 설정 파일을 통해 주입한다.
- secret을 코드에 하드코딩하지 않는다.

## 예외 처리

금지:

- 모든 오류를 `RuntimeException` 하나로 뭉뚱그리기
- 원인을 숨기는 빈 catch 블록
- 로그 없이 예외 무시

권장:

- 상황에 맞는 커스텀 예외 사용
- 사용자에게 노출 가능한 메시지와 내부 로그 분리
- 실패 원인이 드러나는 테스트 작성

## JPA 규칙

Entity 작업은 사용자 승인과 도메인 문서 확인 후 진행한다.

권장:

- 기본 생성자는 `protected`
- 상태 변경은 의미 있는 도메인 메서드 사용
- setter 남발 금지
- 연관관계 변경 시 N+1 가능성 확인

## 트랜잭션 규칙

- 트랜잭션 범위를 불필요하게 넓히지 않는다.
- 조회 작업과 변경 작업을 구분한다.
- 외부 API 호출을 트랜잭션 안에 오래 묶지 않는다.

## 보안 규칙

- password, token, API key 하드코딩 금지
- `.env` 커밋 금지
- 사용자 입력을 그대로 HTML로 렌더링하지 않는다.
- 인증, 권한 변경은 사용자 승인 후 진행한다.

## 검증 명령

일반 코드 변경 후 가능한 범위에서 실행한다.

- `./gradlew compileJava`
- `./gradlew test`
- `./gradlew build`

문서만 변경한 경우 Gradle 검증은 생략할 수 있다.
