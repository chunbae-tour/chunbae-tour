# 작업 결과 보고 템플릿

에이전트는 작업 완료 후 아래 형식을 사용해 보고합니다.

## 기본 형식

```markdown
## 작업 결과

| 항목 | 내용 |
|---|---|
| 사용 하네스 | 예: Community Post |
| 작업 범위 | 예: 게시글 생성/조회 Service |
| 보호 파일 수정 | 없음 |
| 타 도메인 수정 | 없음 |
| 사전 보고 필요 이슈 | 없음 |

## 변경 파일

| 파일 | 변경 내용 | 이유 |
|---|---|---|
| `경로` | 변경 요약 | 목적 |

## 검증

| 검증 | 결과 |
|---|---|
| 테스트 | `./gradlew.bat test` 성공 |
| 미실행 항목 | 없음 |

## 남은 확인 사항

| 항목 | 내용 |
|---|---|
| 정책 결정 필요 | 없음 |
| 리스크 | 없음 |
```

## 사전 보고가 필요했던 경우

사전 보고 후 승인을 받고 진행했다면 다음 표를 추가합니다.

```markdown
## 사전 보고 이력

| 이슈 | 사용자 결정 | 반영 방식 |
|---|---|---|
| 예: `ErrorCode` 추가 필요 | 승인 | `common/error/ErrorCode.java`에 최소 추가 |
```

## 테스트를 못 돌린 경우

테스트를 못 돌렸다면 다음처럼 명확히 적습니다.

```markdown
## 검증

| 검증 | 결과 |
|---|---|
| 테스트 | 미실행 |
| 이유 | Docker 필요, 권한 승인 필요 |
| 대신 확인한 것 | 컴파일 영향 없는 문서 변경만 수행 |
```

## 보고 원칙

- 변경 파일은 표로 정리합니다.
- 보호 파일 수정 여부를 반드시 씁니다.
- 타 도메인 수정 여부를 반드시 씁니다.
- 테스트 실행 여부를 반드시 씁니다.
- 남은 의사결정이 있으면 숨기지 않고 적습니다.
