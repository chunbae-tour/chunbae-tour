# 토큰 효율 규칙

## 핵심 원칙: 필요한 것만, 필요한 때만

---

## 1. 파일 읽기 계층

```
Grep (키워드 검색) → Glob (파일 목록) → Read (전체 읽기)
```

| 상황 | 사용 도구 |
|------|---------|
| 특정 설정값 확인 (`ddl-auto`, `port` 등) | `Grep "ddl-auto" application.yml` |
| 특정 메서드/클래스 위치 파악 | `Grep "methodName" src/` |
| 파일 존재 여부 / 목록 | `Glob "*.sql"` |
| 구현 내용 전체 파악 필요 | `Read` |

**Read는 Grep/Glob으로 충분하지 않을 때만.**

---

## 2. 파일 읽기 범위

- 수정할 파일만 읽는다
- 관련 없는 파일은 Grep으로 필요한 줄만 확인
- 설정 파일 전체 읽기 금지 — 필요한 키만 Grep

---

## 3. 에이전트 스폰 기준

| 조건 | 판단 |
|------|------|
| 파일 3개 이하 읽기 | 인라인 (Read/Grep 직접) |
| 광범위 탐색 (10개+ 파일, 디렉토리 전체) | Explore 에이전트 |
| 1-2개 파일 수정 | cavecrew-builder |
| 코드 위치 파악만 필요 | cavecrew-investigator |

**단순 파일 읽기를 위한 에이전트 스폰 금지 — 메인 컨텍스트에 결과 재주입 비용이 더 큼.**

---

## 4. 작업 시작 시 읽기 순서

```
1. 필요한 파일만 Grep으로 구조 파악
2. 수정 대상 파일만 Read
3. 관련 없는 파일 (application.yml 전체 등) 읽기 금지
```

---

## 5. 병렬 도구 호출

독립적인 Read/Grep은 항상 병렬 호출.

```
Good: Read(A) + Read(B) + Grep(C) — 한 번에
Bad:  Read(A) → Read(B) → Grep(C) — 순차
```

---

## 언제 이 파일을 읽나

새 작업 시작 시 자동 적용. 별도 확인 불필요.
